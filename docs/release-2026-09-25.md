## Rollback

The deployment script pulls the pushed commit, installs dependencies, builds and restarts the service. Before deployment, create a consistent, mode-600 SQLite snapshot with `VACUUM INTO` in `.data` while the service may be active. Record its path and the previous Git commit. For a rollback, stop the service, preserve the current database and WAL files separately, restore the consistent snapshot as `.data/tracking.sqlite` with no old WAL/SHM sidecars, restore the previous code/dependencies/build and start the service. Recheck `pragma integrity_check`, schema version and HTTP health. A code revert alone does not downgrade a migrated database. Rollback should be a deliberate incident action, never part of the automatic deploy.
